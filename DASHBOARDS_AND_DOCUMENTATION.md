The catalog includes all four inventory families and the retype lifecycle families.

## Final metric catalog

Appendix A of `README.md` is the canonical human-readable catalog. Every final metric name is present exactly once with its metric type, complete exporter labels, and unit. The dashboard and documentation test obtains the metric schema from a production collector scrape and compares it with that catalog. It also checks unit-bearing suffixes such as `_bytes`, `_seconds`, `_percent`, `_gbytes`, and `_severity`. The legacy `_mb` and `_gbytes` metric names retain their public spelling, but their values use binary divisors and are documented and rendered as MiB and GiB.

Derived network rates from the GiB counters are rendered as Gibit/s.

The catalog describes exporter labels only. Prometheus adds target labels such as `instance` and `job` while scraping. Dashboard and alert selectors are checked against both sets, including template-variable `label_values` queries, PromQL grouping and matching labels, and alert annotation label references.

## Availability, freshness, retained values, and missing data

An exported value is not automatically a fresh observation. Operators must interpret it with its source state:

| Source or signal | Fresh | Retained | Unavailable or missing |
| --- | --- | --- | --- |
| Exporter target | Prometheus `up{job="openstack-instance-exporter"} == 1` | Not applicable | `up == 0` or the target series is absent; `up` is generated by Prometheus, not OIE. |
| Libvirt | `oie_host_libvirt_ok == 1`; stale age advances from the latest successful atomic domain snapshot | After a prior success, last-good dependent values may remain visible while `oie_host_libvirt_ok == 0` | Before the first complete success, dependent values are omitted. A failed or inconsistent domain cycle is not published as fresh. |
| Conntrack | `oie_host_conntrack_raw_ok == 1`; the dump completed for the enabled address families | After a prior complete success, the last-good snapshot can remain visible for the same instance UUID and fixed-IP identity while stale age increases | Before the first complete success, dependent values are omitted. An incomplete dump does not become a healthy zero. |
| Resource axis | `oie_instance_resource_axis_fresh == 1` and `oie_instance_resource_axis_available == 1` | The last-good axis severity is retained without advancing its EWMA for at most eight collection intervals | `available == 0`; severity is omitted after retention expires. A non-finite or absent observation is a missing sample, not zero. |
| Volume retype | Current guarded XML and block-job observations | Recent terminal rows remain visible within the retention limit | Disabled monitoring, an unavailable source or an expired operation supplies no current observation; see below |
| Threat feed | `oie_host_threat_feed_fresh{list=...} == 1` means enabled with a usable snapshot | A failed refresh retains the last complete snapshot only while the feed freshness policy says it remains usable | `0` means enabled but unusable; `-1` means disabled. All five fixed feed-state series are emitted. |

### Retype observation states

Status code `1` means copying; status code `5` means the Libvirt copy is ready and awaiting pivot; status code `6` means that ready state has persisted for at least ten minutes since OIE first observed it. The job-present gauge remains `1` in all three states. The completion-paced fast poller inspects mirror XML no more often than every five seconds after the preceding attempt completes.

Block-job progress queries run no more often than every fifteen seconds after the preceding query completes, are serialized per domain, and wait thirty seconds after a failed query completes before retrying. Bounded work rotates fairly; a timed-out raw XML call suppresses only same-domain retries until it exits.

### Terminal rows and retention

Terminal status `2` follows a successful XML inspection that finds the saved destination as the live source; status `3` follows one that finds the original source; status `4` is possible only when that inspection finds the mirror gone but cannot match the final source to either saved identity. Recent rows and exporter-observed timestamps remain in memory for one hour and are capped at 256 rows per exporter. An exact repeated source/destination identity retains only its newest row.

### Missing retype observations

Idle volumes have no per-operation retype series, although bounded discovery XML inspection continues during normal collection cycles. Copy-ready and ready-stalled are non-terminal and do not prove Cinder success. Detached or available-volume retypes have no compute-side Libvirt block job and are outside this view. Observation health is `1` when the latest block-job query succeeded and `0` after a query failure; the per-job health and progress fields are omitted while the main Libvirt source is unavailable. Progress is also omitted if its current cursor is unavailable.

A job that becomes too old to reconfirm expires without a terminal status, row, timestamp, or result-counter increment. Recent rows and counters reset on exporter restart.

These per-job intervals are minimum spacing. Shared Libvirt timeout backoff can defer every observation path for at least one minute, and active control/job checks can defer it longer. Block statistics are omitted for a domain with a live disk mirror; CPU, memory and network statistics continue when control/async-job checks permit. Missing observations are represented by the existing freshness and availability metrics.

The corresponding last-success and stale-seconds gauges expose age. A stale-seconds value of `-1` means that source has never completed successfully. Resource-axis panels separately count fresh, retained, and unavailable states so a last-good severity is not mistaken for a current sample.

Optional metrics remain conditional. Conntrack byte and packet features require kernel conntrack accounting. Behavior families require their direction to be enabled. Threat observations require an enabled, usable feed. Device statistics require the relevant Libvirt statistic to exist. OIE omits unavailable observations instead of inventing zeros.

## Persistence and recovery

Behavior, mining, resource, and threat state use the real configured collection interval and elapsed eligible time. Supported `collection.interval` values are **5s through 1m**, with a `15s` runtime default. Incomplete Libvirt or conntrack cycles freeze dependent persistence and cooldown state; they do not count as clean or qualifying observations. Recovery that requires a statistical baseline reinitializes silently before later complete intervals can qualify.

A warning-qualified behavior or mining state means the documented evidence and persistence gates were satisfied. It **does not prove mining**. A configured threat-list match or high threat score **does not prove compromise**, malicious intent, or ownership of the remote endpoint. These are triage signals for operator review.

## Dashboard contract

The five-dashboard Grafana 12 set is intentionally split by operator task:

| Dashboard | Primary questions |
| --- | --- |
| Cluster | Is the exporter reachable? Are Libvirt and conntrack fresh? Which volume retypes are active or recently completed? Which resource axes are fresh, retained, or unavailable? Which instances rank highest by resource, behavior, threat, and attention evidence? |
| Hypervisor | Which compute node is under host, conntrack, CPU, memory, disk, or network pressure, and which instances contribute? |
| Project | Which project owns the observed allocation, usage, pressure, volume retypes, and evidence? |
| Instance | What are the selected instance's identity, resource axes, traffic features, threat-list evidence, and mining evidence? |
| Threats | Which configured feeds are enabled and usable, which contacts and active-flow matches were observed, and which behavior features warrant review? |

### Cluster and project retype tables

The cluster dashboard exposes `up`, source health, last-success age, instance identity, all four resource severity axes, top-instance views, warning-qualified mining evidence, and a full-width retype lifecycle table. The project dashboard includes the same retype table constrained by its existing project and instance variables. Each table is titled **Attached-Volume Retypes Only — Active and Recent**. Raw Prometheus queries intentionally return separate series for status, observation health, job presence, progress, and timestamps; the bundled instant-query table transforms those fields into exactly one row per retained operation.

### RBD identity labels

**Source RBD Pool** and **Destination RBD Pool** display the RBD pool portions of the two saved image identities; they are not Cinder volume-type names. **Source RBD Image** and **Destination RBD Image** display the RBD image basenames, including their `volume-` prefixes; strip that prefix before using either value with `openstack volume show`. Retype telemetry is a compute-local Libvirt view of volumes attached to active domains; detached or available-volume retypes are not visible, and OIE does not query Cinder for authoritative migration state.

Root/boot volumes appear when Libvirt exposes a matching job, but support and outcome depend on the OpenStack and storage path.

### Copy-ready and terminal outcomes

A Libvirt mirror with `ready="yes"` is displayed as **Copy Ready / Awaiting Pivot**, not as completed; after ten exporter-observed minutes it becomes **Ready Stalled / Awaiting Pivot** and remains a present job until pivot or abort. Status **Outcome Unknown** is emitted only after a successful terminal XML inspection cannot match the final live source to the saved source or destination; loss of reconfirmation alone expires the active row without synthesizing a terminal result.

### Current rows and historical data

Retype timestamps, recent rows, and result counters are exporter-process observations held in memory and reset on restart. Terminal rows are bounded, an exact repeated source/destination identity retains only its newest row, and logical progress is not Ceph physical allocation, transferred bytes, or ETA. Exporter expiry ends current emission; Prometheus may retain earlier samples according to its TSDB retention, while the bundled instant table stops showing an omitted row after Prometheus processes the subsequent scrape.

The threat dashboard exposes the fixed-cardinality feed state as `1` usable, `0` enabled but unusable, and `-1` disabled. Long-window new-remote panels show the largest observed per-collection burst on any one fixed-IP/address-family series. They use `max_over_time`, not a sum of cached gauge samples, and do not count distinct IPs across seven or thirty days.

### Query matching and display units

Every dashboard expression is parsed by `promtool`. Every referenced `oie_*` metric and selector label must exist in the final schema, and every OIE panel or dashboard-variable selector is explicitly constrained to `job="openstack-instance-exporter"`. Host filters use Grafana's regex-safe multi-value interpolation and anchor the complete hostname plus an optional numeric scrape port, so OIE and node-exporter endpoints on the same host line up without prefix-matching similarly named hosts.

Display units are explicit for every non-table OIE panel, and every time-series panel explicitly sets Grafana stacking mode to `none`. Process CPU seconds per second are multiplied by 100 before using a percent unit, binary-scaled counters use IEC display units, and network rate titles distinguish throughput from cumulative volume. VM scheduler-delay panels prefer Libvirt delay/steal and use wait only as a fallback; they do not add the two runqueue-delay aliases.

The project conntrack endpoint-load ratios sum fixed-IP endpoint observations: an east-west flow attributed to two project endpoints can contribute twice, so these diagnostic ratios are not unique-flow shares and can exceed 100%.

## Alert requirements

The bundled operational alert pack contains one concise group with 82 definitions and ten recording rules. It enables 33 alerts by default; 49 informational diagnostics are opt-in. All v1.2.0 alert names remain present. Environment-specific workload thresholds still require operator review and tuning before production use.

Alert requirements are source-local. Libvirt-derived workload rules require current Libvirt health, conntrack-derived rules require current conntrack health, and mixed rules require both. Range rules also require a matching healthy `up` and source cohort across the complete lookback. Feed-derived rules use the feed's current tri-state health. Retained workload data can remain visible for diagnosis but cannot start or extend a bundled workload alert. All 82 bundled rules have executable lifecycle coverage, and all v1.2.0 alert names remain present.

`OpenStackInstanceVolumeRetypeReadyStalled` warns only for status `6` with healthy Libvirt. `OpenStackInstanceVolumeRetypeObservationUnhealthy` warns only after two continuous minutes of block-job query failure while the main Libvirt source remains healthy, and is suppressed when the same operation is already ready-stalled. Both retype rules use warning severity.

## Runtime defaults and deployment

The runtime defaults table in `README.md` contains all 51 CLI flags and is compared directly with the production flag registry. A documentation-only change cannot silently change a default. Release commands pass `VERSION=v2.0.0`, which is also the Makefile default.

The supported deployment is **one exporter per compute node** on amd64 Ubuntu 22.04 or Ubuntu 24.04 with local QEMU/Libvirt. The shipped Ansible role runs the service as root for direct local Libvirt and raw conntrack access; raw conntrack Netlink collection requires `CAP_NET_ADMIN` privilege. Threat downloads additionally need DNS and outbound HTTPS when enabled. The shipped role and systemd behavior are detailed in `OPERATIONAL_CONFIGURATION.md`.

## Measured scale boundary

On the documented reference host, the supported five-second synthetic processing envelope is **500,000 conntrack entries and 500 active domains**. One million and two million entry cases were measured, but they are planning boundaries with longer practical intervals, not five-second support claims. Kernel delivery, slow Libvirt RPC, noisy-neighbour CPU pressure, scrape transport, and logging backends are not modeled by the synthetic harness. Operators must rerun the scale gate on representative hardware.

## Visibility and inference limits

OIE reads metadata and counters; it does not capture packet payload or reconstruct application sessions. Encryption is therefore neither broken nor interpreted. Asymmetric routing, hardware or software offload, flows that bypass the observed conntrack table, source outages, migration, and scrape gaps can reduce visible evidence.

Zone-first attribution is preferred. With **overlapping tenant IPs** and no reliable conntrack-zone context, a flow may not map uniquely to one instance; host totals remain useful while per-instance attribution can be incomplete or ambiguous. Fixed-IP discovery and exact instance lifecycle identity also bound attribution.

Threat-feed results are bounded by source quality, update cadence, list scope, and the exporter's usable-snapshot policy. Behavior scores compare visible features with an internal baseline; ordinary workload changes can look unusual, and deliberately quiet behavior can remain below thresholds. Mining port and endpoint evidence is not protocol or economic proof. Operators should corroborate with cloud control-plane records, tenant context, network controls, and—where policy permits—packet or application telemetry.

## Validation

Run the focused gate from the repository root:

```bash
make docs PROMTOOL=/path/to/promtool
```

The mandatory required-CI workflow runs the same target after the public-contract, replay, and scale gates. `make check` includes it before the Ansible and release gates. The dashboard and documentation test also byte-freezes every prior golden contract and replay fixture used as its baseline, so final asset work cannot rewrite earlier acceptance evidence unnoticed.
